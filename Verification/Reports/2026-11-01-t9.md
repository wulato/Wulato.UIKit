## 实现

- UIBindingMarker 仅保存序列化创作数据，不引用 UnityEditor。字段名与目标 Component 显式配置；对象重命名不改变绑定关系。每个 View 显式选择一个注册 Prefab，支持排除作者基底、注册其 Variant；已知 Editor-only View 不进入运行时映射，损坏脚本仍被拒绝。
- Editor 菜单提供 UIRoot、一次性业务 partial 创建、生成、写回恢复及校验。生成目录固定为消费宿主 Assets/Wulato.UIKit.Generated，不修改包缓存或业务源码。
- UIBindingAssemblyRouter 使用 CompilationPipeline 的实际程序集及 asmdef 资源 GUID。自定义程序集通过 GUID asmref 接收自己的 partial/provider；Assembly-CSharp 不生成 asmdef/asmref，生成根无统领程序集。挂载/写回后再次核对真实编译归属。
- Bindings 为业务类型原命名空间、类名和可见性的 partial 私有序列化字段；引用在 OnCreate 前可用。类型 key 默认采用脚本资源 GUID，可显式配置；provider 输出明确的 Add<TView> / Add<TView,TArgs> 桥接及策略。
- 每业务程序集创建自己的 provider 类型/资产，UIRegistry.asset 用序列化引用汇总，运行时构建不可变快照。Core 不反向引用业务程序集，自定义业务程序集不引用 Assembly-CSharp，不扫描程序集发现 provider。
- 输入指纹包含业务源脚本/GUID、实际程序集/asmdef GUID、配置及目标组件稳定标识。拥有的源码与 asmref 记录哈希；重路由清理旧产物时检查所有权并保留业务文件及用户文件。
- Library 中持久化待写回状态。编译/Domain Reload 后恢复组件挂载、SerializedObject 引用及 provider 写回；没有代码变化时直接完成，避免等待不会发生的 Reload。构建回调只校验，缺失、过期、重复、非法引用、错误路由或待完成状态均阻止构建。
- run.py 新增 codegen/check-generated；继续使用既有排他锁、固定版本启动、真实日志、指纹与原始文件哈希。没有新依赖、包版本或 ProjectSettings 修改。

实现位置裁定：UIRegistryProvider / UIRegistryBuilder / UIRegistrySnapshot 已在 Core/UIRegistry.cs 中实现并满足契约，因此直接复用，没有重复声明或为文件清单拆分已有 Unity 脚本/GUID。执行记录更新现有计划；未新增重复设计或任务文档。
