## 修复与集中审查

模块按 RED→GREEN 推进，关键原始记录见实施计划和 Artifacts/uikit/phase3。集中审查修复明确 address 中方括号被误判为子资产键的问题，保留 label/多匹配拒绝；新增精确地址用例。前置 trace 命名最初未满足既有逐例证据校验，修正后刷新相同专项矩阵，没有删除逐例检查或放宽缺失证据判定。

干净安装发现 Unity 的 Player 编译候选表含未引用 TestRunner，SDK 自动预编译候选又含 NUnit。安装证据采集改为记录完整编译引用图，并从消费源码/所选 UIKit 根计算闭包；预编译候选须与实际 Editor 编译 Runtime DLL 的导入元数据求交。保留候选、全部边、根、真实 DLL/哈希/导入和未引用项，实际测试/验收依赖、缺 DLL 或哈希不符仍失败。新增正负 Python 用例证明未引用候选不误判、真实 NUnit/TestRunner 依赖仍被拒绝。原失败记录保留；没有新增第三方依赖或执行 Player 构建来绕过问题。

此元数据证据限于 Editor 安装编译，不证明目标 Player 条件编译、裁剪或 IL2CPP 行为。UnityEngine.UnityTestProtocolModule 是内建引擎模块，不能按任意 test 子串当作 NUnit/TestRunner。

集中作者审查已覆盖验收追踪、三类资源路由、租约/取消/迟到所有权、生成硬引用、依赖方向、版本、资产 GUID 和证据完整性。根 packages-lock、ProjectSettings、AGENTS.md 与 .vscode 既有工作保留；根锁文件仍为原54行新增、ProjectSettings仍为原1行替换。验证宿主生成资源保持 Unity 的序列化格式，没有为清理生成 YAML 空白而改写最终证据输入。
